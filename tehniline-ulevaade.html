3. Andmeallikad: TME API ja Element14

Projekt kasutab kahte elektroonikamüüja API-t, kumbki eraldi Airflow DAG-iga.

TME API v2

TME on Poola elektroonikamüüja. Projekt kasutab nende REST API v2 kolme otspunkti:

  1. POST /auth/token: küsib OAuth 2.0 access tokeni (HTTP Basic Auth: API_PRIVATE_KEY:API_APP_SECRET)
  2. GET /products/search?phrase=…: otsib tootesümbolid kategooria järgi (nt resistors)
  3. GET /products/data?symbols[]=…: laeb hinnad ja laoseisu (kuni 50 sümbolit korraga)

Element14 / Farnell UK API v1.2

Element14 (Farnell UK) on Briti elektroonikamüüja. Autentimine käib API võtmega otse URL-parameetrina (ELEMENT14_API_KEY). Üks päring tagastab tooted koos hindade ja laoseisuga:

  1. GET /catalog/products?term=any:…&storeInfo.id=uk.farnell.com&callInfo.apiKey=…&resultsSettings.responseGroup=large: otsib tooted ja laeb hinnad ning laoseisu ühest päringust (kuni 100 toodet korraga)

4. Airflow DAG: töövoo kolm sammu

DAG käivitub kord päevas (@daily) ja koosneb kolmest järjestikusest taskist:

laadi_kataloogid
PythonOperator
▶
dbt_run
BashOperator
▶
dbt_test
BashOperator
1
laadi_kataloogid: hangib TME API-st kõigi 6 tarnija tootesümbolid, hinnad ja laoseisu. Salvestab tulemuse staging.tooted_raw tabelisse päevase hetktõmmisena. ON CONFLICT DO NOTHING tagab, et sama päeva andmeid ei dubleerita, isegi kui task kordub.
2
dbt_run: käivitab dbt seed (tarnijad.csv → andmebaas) ja seejärel dbt run (kõik SQL-mudelid järjekorras: staging → intermediate → marts).
3
dbt_test: kontrollib andmekvaliteeti (mitte-null väljad, tarnijate koodide lubatud väärtused). Kui test ebaõnnestub, logitakse viga Airflow UI-s.

5. Andmemudel: kuidas andmed dbt-s liiguvad

dbt jagab andmed nelja kihti. Iga kiht on Postgresist eraldi skeemis (staging, intermediate, marts):

staging.tooted_raw
Airflow laeb siia toorandmed · tabel · skeemis staging
↓ dbt view
stg_tooted
Puhastus + loplik_hind + on_laost_otsas · view · skeemis staging
↓ dbt view + JOIN tarnijad
int_toode_hinnamuutus
Päevane hinnamuutus LAG()-ga + tarnija info JOIN · view · skeemis intermediate
↓ dbt table (materialiseeritud)
mart_tarnija_kokkuvote
Koondstatistika tarnija kaupa · viimane päev
mart_kategooria_hinnajaotus
Hinnajaotus kategooriate kaupa · trendid

Miks kolm kihti?

  • Staging: puhas koopia toorandmetest, minimaalne töötlus. Kerge muuta ilma midagi lõhkumata.
  • Intermediate: äriloogika (hinnamuutused, tarnija ühendamine). Staging ja marts ei sõltu teineteisest otse.
  • Marts: lõpptabelid, mida Superset loeb. Materialiseeritud tabelina (mitte view), et päringud oleksid kiired.
tarnijad seed on eraldi viitetabel. Tarnijate nimed ja riigid on CSV-s, mitte hardcoditud SQL-i. Uue tarnija lisamiseks piisab ühest uuest reast CSVs.

6. Andmebaas: PostgreSQL Neonis

Andmebaas asub Neon-is (serverless Postgres pilves). Ühendusstring on .env failis muutuja DATABASE_URL all. Nii Airflow kui Superset ühenduvad sama andmebaasiga:

  • Airflow kirjutab → staging.tooted_raw
  • dbt loob/uuendab → kõik view-d ja tabelid skeemides staging, intermediate, marts
  • Superset loeb → marts.*

Skeemid ja tooted_raw tabel luuakse käsuga psql $DATABASE_URL -f init/01_create_schemas.sql. See tuleb teha üks kord enne esimest käivitust.

staging.pipeline_runs on auditilogi. Iga DAG-käivituse kirje sisaldab aega, kirjete arvu ja staatust. Kasulik silumiseks.

8. Konfiguratsioon: .env fail

Kõik saladused ja ühendusandmed elavad .env failis. .env.example näitab vajalikud muutujad:

  • DATABASE_URL: Neoni ühendusstring (nii Airflow kui Superset kasutavad seda)
  • POSTGRES_HOST / USER / PASSWORD / DB: dbt profiili jaoks eraldi
  • API_PRIVATE_KEY / API_APP_SECRET: TME OAuth2 kredentsiaalid
  • ELEMENT14_API_KEY: Element14/Farnell API võti
  • SUPERSET_ADMIN_USER / PASSWORD: Superseti admin
.env faili ei tohi giti panna. See on .gitignore-is. Igale meeskonnaliikmele tuleb anda oma koopia.

10. Andmekvaliteet: 59 automaatset testi

Iga dbt test käivitusel kontrollitakse 59 automaatset andmekvaliteedi testi:

S
Staging layer (30 testist): kontrollib lähteandmete kvaliteeti:
  • not_null: run_id, tarnija_kood, sumbol, mpn, nimi, tootja, kategooria, hind, loplik_hind, valuuta, on_laost_otsas, laetud_kell, laetud_kuupaev
  • relationships: tarnija_kood → tarnijad seed
  • unique: tarnijad.tarnija_kood
I
Intermediate layer (17 testist): kontrollib transformatsioonide õigsust:
  • not_null: kriitilised väljad int_toode_hinnamuutus ja int_tootepakkumised_paeviti mudelites
M
Marts layer (12 testist): kontrollib lõppandmete kvaliteeti (Superset jaoks):
  • not_null: kõik mart-mudelite võtmeväljad
  • unique: mart_KPI.laetud_kuupaev, mart_tarnija_kokkuvote.tarnija_kood
Testide käivitamine: dbt test --profiles-dir . käivitab automaatselt iga DAG-i taskis dbt_test. Kui test ebaõnnestub, logitakse viga Airflow UI-s ja peatab pipeline.
